# Analysis 报告：证据与详细轨迹

## 目标

让每题报告能直接说明回答依据，并把可读的智能体执行轨迹与原始工件连接起来，而不把正文变成原始 JSON 日志。

## 证据归属

证据以 `TurnRecord.produced_refs` 和 `TurnRecord.consumed_refs` 为题目归属的唯一依据；不得以全局 `EvidenceRecord.turn_id` 过滤。每项显示：

- 语义描述和能力名称；
- `本题生成` 或 `复用前序分析`；
- 证据工件的相对链接。

只显示与本题结论关联的代表性证据，并说明被省略的重复场景数。没有任何可追溯证据时，才显示无证据提示。

## 轨迹层次

主报告的“实际分析过程”保留每个工具调用的语义步骤、成功状态和耗时。每题新增“详细执行轨迹”链接到 `turns/<ordinal>/trace.md`。

该页按调用顺序列出：工具/能力、脱敏后的输入、结构化输出摘要、状态、耗时，以及对应 `tool-results/<turn-id>/<call-id>.json` 的链接。它不展示模型隐含推理，也不复制完整输出；需要完整记录时，读者可打开对应 JSON 或全局 `trace/events.jsonl`。

## 可靠性与测试

报告渲染只读现有 workspace；缺失或畸形 trace/tool-result 工件必须作为局部提示，不能改写已提交答案或中止报告。测试覆盖：全局登记证据仍可按题展示、复用证据标记、详细轨迹的输入/输出与原始工件链接、以及缺失工件降级。
