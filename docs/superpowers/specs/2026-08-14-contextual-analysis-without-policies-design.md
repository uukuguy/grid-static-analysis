# 连续 Analysis 去除遗留 Policy 设计

## 决策

`analysis` 是单一连续会话。每条指令必须以已投影的 `AnalysisContext` 和会话历史解释；后续题目中的省略主语继承已打开的模型上下文。旧的 `static-analysis-v1` 不再是产品概念、工具能力或答案来源。

## 第二题语义

在“已打开 IEEE-39”之后的“母线电压正常运行范围是多少”指 IEEE-39 模型的电压约束，而不是泛化知识题。

1. 查询模型已发布的母线电压下限/上限；
2. 若存在，回答为 IEEE-39 模型约束；
3. 若不存在，明确该模型未定义正常运行边界。可报告潮流求得的实际 `vm_pu`，但不得据此评价正常、低压或高压。

## N-1 与风险结果

潮流和 N-1 保留计算事实：收敛状态、每个母线 `vm_pu`、每条支路 loading。只有模型自身公开的约束才能产生 `bus_voltage_low`、`bus_voltage_high` 或 `line_overload` 评价；没有约束时输出原始极值/排序，并将评价状态标为未定义。

## 移除范围

删除 `configs/policies/static-analysis-v1.json`、`analysis.policy.describe`、N-1 capability 的 `policy` 输入/输出、静态常量、旧离线电压范围知识、策略技能说明、策略验证用例和所有相关断言。同步移除把“电压范围”强制为零工具知识题的验证规则。

## 连续上下文要求

分析运行器继续单 Pi 进程、逐题 prompt；每题开始前注入的结构化 context view 必须包含活动模型、模型约束可用性、前序结果和已验证事实。系统提示明确要求：省略模型名的后续指令先使用活动模型与 context view，不得退回旧离线知识。

## 验收

- 不再存在 `static-analysis-v1` 或 `analysis.policy.describe` 的已发布运行时路径；
- 第二题在连续 IEEE-39 测试中调用模型约束查询，而非知识捷径；
- IEEE-39 无公开约束时得到“模型未定义边界”的有效答案，而非执行失败；
- N-1 仍有可追溯原始指标与场景证据；无模型约束时不产生伪越限；
- 单元、端到端、离线及脚本化验证全部通过，并替换旧策略题用例。
